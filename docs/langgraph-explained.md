# LangGraph 在这里是什么 · LangGraph Explained

> 一句话：LangGraph 是这一套流程的“指挥 / 流程控制器”——决定谁先干、能不能一起干、干完传给谁、什么时候暂停等人、什么时候在存档点继续。

如果你把它理解成“**负责人事安排的调度 + 一本共享工作本 + 暂停/续跑能力**”，就够了。

---

## 1. 为什么不就用几个 Python 函数串起来？

我们确实可以在代码里写：

```
库存分析() 
价格分析()
供应商分析()
制度判断()
```

但问题在于这个流程有特殊要求：

1. **想并发**：库存/价格/供应商其实可以“同时算”，串行就慢。
2. **有时要停**：遇到 REVIEW，要在中间“暂停、等一个人类点按钮”，等几小时甚至几天都不怕。
3. **暂停后要续跑**：等人类批完，要从“暂停点”继续往下，而不是把前面每个分析全部重跑一遍。
4. **要看得清新流程**：一条链（node）+ 谁到谁（edge）+ 抉择（if）放在一起，容易读、容易改。

而 LangGraph 把这些（并行、可中断、可恢复、看得清的图）都内建了——这正好对着这些诉求。这就是为什么不是“一行 Python 从头到尾”。

> 普通 Python 是一张“只能从头走到尾的单程票”；LangGraph 是一张“可以分支、可以中途存档、可以回来继续”的地图。

---

## 2. 一些名词，先用中文

| 名词 | 人话 | 在我项目里的对应 |
| --- | --- | --- |
| **Node**（岗位） | 一个干固定活的位置 | 库存分析、价格分析、供应商分析、制度表、Agent5、人工审批、采购执行都是一个个 Node |
| **Edge**（线路） | 上一个岗位做完把下一步交给谁 | 谁跟谁连、谁是结束 |
| **State**（共享工作本） | 所有人共用的一个“记事本”，写到上面的结果别把自己一份私藏 | 例如 `analysis_inventory`、`policy_decision`、`agent5_analysis` 都往里写 |
| **Conditional Edge**（分支路） | 看工作本再决定走哪条路 | 制度表执行完根据 status 去 NO_PURCHASE / PURCHASE / REVIEW |
| **Fan-out**（分叉） | 一个开始分出多个人同时干 | START 同时去三个分析 |
| **Fan-in**（聚敛） | 多个人干完回到同一处收口 | 三个分析做完都汇到制度表 |
| **interrupt()**（暂停） | 走到这“先停，等待外部给你一个值” | REVIEW 后等人点 approve/reject |
| **Command(resume)**（续跑指令） | 说要“我用这个答案继续” | 人点通过= `Command(resume={"approved":True})` |
| **Checkpoint**（存档） | 把“我走到哪一步”存档 | 存在 Redis 里，重启也能恢复 |

---

## 3. interrupt 到底怎么“暂停”

它不像 sleep 等着，而是 LangGraph 给的“现场存档 + 返回一个中断通知”。这一轮执行到此为止、把状态存档；框架把需要给人看的信息放进返回值里。真人工点了之后，再用同一存档号继续。正是因为“存档在 Redis”，整个人等多久都不怕服务重启。

> 类比：做菜到一半放一个“存档”，盖上保鲜膜出去；领导批准后回来从“接着把调料下锅”那一行继续，不会把前面切菜再切一遍。

## 4. ARCHI 在本项目的精确流向（直白版）

```
START
   → (并行) 库存 / 价格 / 供应商 三分析
   → 都汇到 deterministic_policy
   → 制度表给 status：
        NO_PURCHASE ⇒ 结束
        PURCHASE    ⇒ purchase_agent（去写单+入库存）
        REVIEW      ⇒ Agent5 解释 => purchase_approval(等人) => 通过则回 purchase 线 / 拒绝则结束
```

代码在 `app/graph/workflow.py`（接线），每个岗位逻辑在 `app/graph/nodes.py`，字段声明在 `app/graph/state.py`。

## 5. 面试追问版（记一下人话）

- 为什么 Multi-Agent？为了把“确定性算术/制度判断”和“解释性 LLM”解耦，各司其职。
- 为什么需要可恢复？因为有真人在流程中间审批，程序不能卡在内存里等半天。
- Fan-out/Fan-in 就图“三个只读分析可并发”，然后汇聚到一个决策点。

---

## 6. 红线圈起来（非实现）

LangGraph 这里 **不负责直接写 MySQL**，不负责“自己做采购执行”，也不带 Lock；它只做“编排/状态/暂停续跑”。把数据库、锁这类的活分给别的层。
